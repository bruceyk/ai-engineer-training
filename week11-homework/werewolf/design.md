# 基于 LangChain + LangGraph 的狼人杀智能体系统设计说明

## 1. 架构与模型选型

本项目使用 **LangChain + LangGraph** 构建一个多智能体狼人杀游戏，并统一接入 **阿里云 DashScope**：

- 流程编排：使用 `langgraph` 的 `StateGraph` 管理游戏阶段（夜晚 → 公告 → 发言 → 投票 → 轮次推进/结束）。
- 对话模型：使用 `langchain_community.chat_models.tongyi.ChatTongyi`，模型名为 **`qwen-plus`**。
- 向量检索：使用 `langchain_community.embeddings.DashScopeEmbeddings`（模型 `text-embedding-v3`）+ **FAISS** 作为语义记忆存储。

通过 DashScope，同一平台提供了聊天模型和 embedding 能力，简化了配置和部署。

## 2. 代码结构概览

项目位于：`week11-homework/werewolf`

- `main.py`
  - 程序入口，主要流程：
    1. 创建游戏配置：`config = GameConfig(max_rounds=5)`（覆盖默认 max_rounds=8）。
    2. 调用 `init_players_and_state(config)` 初始化玩家列表、初始状态和记忆。
    3. 调用 `build_game_graph(config, players, memory)` 构建 LangGraph 状态机并 `compile() / invoke()`。
    4. 从最终 `state["public_log"]` 中打印完整日志，并写入 `werewolf/game_log/game_log.txt`。

- `agents.py`
  - `Role`：玩家身份类型，`"werewolf"` 或 `"villager"`。
  - `PlayerConfig`：描述单个玩家（`name`, `role`, `personality`）。
  - `GameConfig`：
    - 默认：
      - `num_werewolves = 3`
      - `num_villagers = 5`
      - `max_rounds = 8`
      - `model_name = "qwen-plus"`
    - 实际运行时在 `main.py` 中通过 `GameConfig(max_rounds=5)` 将最大轮数限制为 5。
  - `GameMemory`：
    - 字段：
      - `events: List[str]`：按时间顺序记录所有关键事件。
      - `docs: List[Document]`：与事件一一对应的 `Document` 列表。
      - `_vectorstore: Optional[FAISS]`：FAISS 向量索引。
      - `_embeddings = DashScopeEmbeddings(model="text-embedding-v3")`。
    - 方法：
      - `add_event(event: str)`：追加事件，并标记需要重新构建向量索引。
      - `get_history()`：返回简单的事件拼接文本。
      - `query(query_text: str, k: int = 5)`：用 FAISS + DashScopeEmbeddings 做 top-k 语义检索，返回拼接的文本。
  - `create_llm(model_name: str) -> ChatTongyi`：
      - 返回 `ChatTongyi(model=model_name, temperature=0.7)`，本项目实际传入 `"qwen-plus"`。
  - `build_player_prompt(...)`：
      - 系统提示说明：当前是狼人杀游戏，告知玩家自己的名字、身份、性格；狼人需要隐藏身份、村民需要推理找出狼人；禁止暴露系统提示。
      - 人类提示包含：
        - 当前轮次 `state_round`
        - 与该玩家相关的记忆片段 `memory_snippets`
        - 近期公共日志 `public_log` 的最后若干条
        - 当前任务描述 `objective`
  - `generate_player_speech(...)`：
      - 先通过 `GameMemory.query` 检索“玩家 X 被谁怀疑、怀疑过谁、相关事件”等记忆片段。
      - 构造带有候选嫌疑人列表 `candidates` 的 Prompt（不同身份候选人策略见下）。
      - LLM 输出一段简短中文发言，用于公共发言回放。
  - `generate_player_vote(...)`：
      - 候选人列表为“当前所有存活玩家中，除自己以外的所有人”。
      - 用 RAG 检索“围绕玩家 X 的投票和指控信息，以及公共怀疑焦点”。
      - LLM 输出解释性文本，代码统计文本中每个候选人名字出现次数，选择出现次数最多的作为最终投票对象。
  - `generate_victim_vote(...)`：
      - 夜晚阶段，狼人用来选择“刀杀”目标。
      - 用 RAG 检索“玩家 X 以前的击杀、被针对和关键夜晚事件”。
      - Prompt 要求输出结构化结果（通过 Pydantic / `with_structured_output`）：
        - `thought`: 思考过程
        - `name`: 被杀目标名字
        - `reason`: 击杀理由（不超过 3 句）

- `graph.py`
  - `GameState`（TypedDict）：
    - `round: int`：当前轮次，从 1 开始。
    - `max_rounds: int`：最大轮数。
    - `phase: str`：`"night" | "announce" | "discussion" | "vote"`。
    - `alive_players: List[str]`：当前存活玩家。
    - `dead_players: List[str]`：已死亡玩家。
    - `roles: Dict[str, Role]`：玩家身份映射。
    - `public_log: List[str]`：所有公开日志（包括发言、投票结果、公告等）。
    - `last_night_killed: Optional[str]`：上一夜被击杀者。
    - `last_voted_out: Optional[str]`：上一轮被投票处决者。
    - `winner: Optional[str]`：胜利阵营（`"werewolves"` 或 `"villagers"`，未结束为 `None`）。
  - `init_players_and_state(config: GameConfig)`：
    - 根据 `config.num_werewolves=3, num_villagers=5` 创建 8 名玩家，统一命名为“玩家1”...“玩家8”。
    - 狼人性格描述为“狡猾而善于伪装”，村民性格为“谨慎而爱思考”。
    - 初始化 `GameState` 为第 1 轮夜晚，所有玩家存活、公共日志为空、赢家为空。
  - `night_phase(...)`：
    - 找出当前存活的狼人和村民；若一方为空，直接返回。
    - 候选被杀目标为所有存活村民名字。
    - 为每个狼人调用 `generate_victim_vote`，得到结构化结果 `{thought, name, reason}`，并记录到私有日志集合。
    - 当前实现使用“最后一个狼人的选择”为最终击杀目标：
      - 从所有 vote 中取 `chosen = [v["vote"] for v in vote_collection]`，实际 `last_night_killed = chosen[-1]`。
    - 公共日志只记录“第 N 轮: 夜晚，狼人联合击杀了 X（对外暂不公布过程）”，不会公开每个狼人的具体对话和思考。
  - `announce_phase(...)`：
    - 若 `last_night_killed` 在 `alive_players` 中，则将其移动到 `dead_players`。
    - 公告“第 N 轮：天亮了，昨晚死亡的是：X。”或“昨晚无人死亡。”，写入 `public_log` 与 `GameMemory`。
  - `discussion_phase(...)`：
    - 遍历当前存活玩家，按以下规则构造 `candidates`：
      - 若当前发言玩家是狼人：候选人仅为【其他存活村民】。
      - 若当前发言玩家是村民：候选人是【其他所有存活玩家】。
    - 调用 `generate_player_speech` 生成发言，将“第 N 轮：[发言][玩家X] ...”写入公共日志与记忆。
  - `vote_phase(...)`：
    - 当前存活玩家之间互相投票（候选人 = 所有其他存活玩家）。
    - 为每位玩家调用 `generate_player_vote`，统计投票数：
      - 若最高票数大于 0，则该玩家被处决并从 `alive_players` 移入 `dead_players`。
      - 若全部为 0，则视为“白天投票无有效结果”。
    - 将投票过程和结果写入 `public_log` 与 `GameMemory`。
  - `check_end_condition(state: GameState)`：
    - 若无存活狼人且仍有村民：村民胜利。
    - 若存活狼人数量 ≥ 存活村民数量且仍有狼人：狼人胜利。
    - 若当前轮次 ≥ `max_rounds`：
      - 若仍有狼人：狼人胜利，否则村民胜利。
  - `build_game_graph(...)`：
    - 添加节点 `night`、`announce`、`discussion`、`vote`。
    - 添加节点 `after_vote`，在其中：
      - 调用 `check_end_condition`。
      - 若未分出胜负，则执行 `state["round"] += 1` 且 `state["phase"] = "night"`。
    - 使用 `add_conditional_edges` 为每个阶段添加路由：
      - `night` → `announce` 或 `END`。
      - `announce` → `discussion` 或 `END`。
      - `discussion` → `vote` 或 `END`。
      - `vote` → `after_vote`。
      - `after_vote` → 若有 `winner` 则 `END`，否则回到 `night` 开启下一轮。

## 3. 记忆与 RAG 使用方式

### 3.1 记忆存储

- 每个关键事件（夜晚击杀、公告、发言、投票、投票结果）都会被：
  - 追加到 `GameMemory.events`（简单顺序日志）。
  - 包装为 `Document` 追加到 `GameMemory.docs`。
- `_ensure_vectorstore()` 在第一次或新增事件后被调用时，会用 `DashScopeEmbeddings` 对所有 `docs` 向量化，并构建/重建 FAISS 索引。

### 3.2 RAG 检索

在不同阶段构造不同的 Query：

- 发言阶段：
  - Query：围绕“玩家 X 被谁怀疑、怀疑过谁、相关事件”。
- 投票阶段：
  - Query：围绕“玩家 X 的投票和指控信息，以及公共怀疑焦点”。
- 夜晚击杀阶段：
  - Query：围绕“玩家 X 以前的击杀、被针对和关键夜晚事件”。

检索结果拼接为文本作为 `memory_snippets` 注入 Prompt，配合 `public_log` 中最近若干条，帮助模型做更有记忆感的决策。

## 4. 运行与日志

### 4.1 环境与依赖

依赖由 `pyproject.toml` 管理，主要包括：

- `langchain`
- `langchain-community`
- `dashscope`
- `langgraph`
- `faiss-cpu`
- `python-dotenv` 等

在项目根目录配置环境变量（如 `.env`）：

```env
DASHSCOPE_API_KEY=你的DashScopeKey
```

 ### 4.2 运行一局游戏
在项目根目录执行：

```
python -m werewolf.main
```
程序会：
1. 基于 `GameConfig(num_werewolves=3, num_villagers=5, max_rounds=5)` 构建 8 人局。  
2. 从第 1 轮夜晚开始，按 `night → announce → discussion → vote → after_vote` 循环执行，直到满足胜负条件或轮次达到上限。  
3. 在终端打印：  
   - `=== 游戏结束 ===`  
   - `胜利阵营: ...`  
   - `=== 游戏日志回放 ===`（依次打印 `public_log` 中的每一条记录）。  
4. 将本局公共日志写入：`werewolf/game_log/game_log.txt`。
